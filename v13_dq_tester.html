How to use this tester

Getting started

1. Paste your OpenAI API key (get one at platform.openai.com/api-keys). It stays in your browser — never stored.

2. Pick a test scenario from the dropdown. Fields auto-fill.

3. Click ▶ Run First Question. The tool calls both prompts and shows the result.

4. Select an answer and click the Submit button to continue the conversation until the prompt decides it has enough info.

Reading the output

MULTI_SELECT means tap multiple answers before submitting. SINGLE_SELECT replaces on each tap.

💡 needsEducation means the Education Text prompt was also called. Look for the yellow lightbulb box below the choices.

🏠 home profile or ⭐ memories means some choices were pre-answered from existing data — look for the blue dot on those choices. Prefilled choices should also show a PERSONALIZATION subtext line: "Based on your home profile", "Based on your past project", or "Based on your details" (project summary signal).

Note on subtext: SOCIAL subtext ("Popular with neighbors") requires a backend aggregate signal. In 5 scenarios (house cleaning, carpet cleaning, dog walking, interior painting, lawn care) a [social: ...] marker has been added to the most realistic "most popular" choice — this simulates the backend signal so you can see how SOCIAL subtext renders. It appears with a 🧪 simulated badge so it's clear it's mock data. PERSONALIZATION subtext fires whenever a choice is prefilled from home profile, memories, or a direct project summary signal.

Expand Raw JSON output under any question to see the full API response from both prompts.

What triggers education text

Square footage, duration/coverage, unit/appliance age, technical jargon in answer choices, and IMAGES questions are always-on. High-skip-rate questions fire when the backend sets skipSignal = true.

Scenario tags

education: ___ — this scenario has an RF question that should trigger a 💡 education lightbulb (budget, sq footage, unit age, technical jargon in choices, duration/coverage, photos). If you run it and see no 💡, that's a bug.

education: budget — specifically tests budget question ordering (ask last) and education text pairing. Budget should always appear after all skill, scope, logistics, and preference questions. The 💡 should explain typical price ranges for the service.

prefill: home profile — home profile data is present; the prompt should use it to pre-answer or confirm certain choices (blue dot = prefilled).

prefill: memories — past-booking memories are present; the prompt should prefill or personalize using them.

personalization likely — expect PERSONALIZATION subtext on at least one choice ("Based on your past project" or "Based on your home profile").

multi-select — at least one RF question should render as MULTI_SELECT. Check that "None of these" appears as the last option.

allowsNone: add-on Q — one or more RF questions are marked is_required: false. The prompt should always offer "None" and never re-ask if declined.

scheduling Q → defer to last — the scheduling question is at RF position 1. The prompt should skip it and return to it only after all other questions are covered. If the customer already answered a scheduling question upfunnel, do not re-ask downfunnel.

non-home location — non-home category; the prompt must not use home profile data to infer location or property details.

age of participant — the RF includes an age or grade question. Participant age determines which pros are eligible — never skip, especially for tutoring, lessons, and personal services. Ask using age ranges; never ask for an exact age or DOB.

photos likely — the scenario should trigger a LLM-generated IMAGES question. IMAGES questions never come from RF. The LLM decides when to ask based on the scenario. If no IMAGES question appears, that's a bug. Education text always fires on IMAGES questions (category 6).

zip code expected — removed May 19, 2026. Zip code is now handled by a hardcoded question outside the prompt and should never appear in prompt output. This tag has been retired.

Custom scenarios

Select — Custom input — at the top of the dropdown and fill in any service category, summary, home profile, and RF questions to test a category not in the list.

Model tips

gpt-4.1 — most accurate, use for real testing.
gpt-4.1-mini — faster and cheaper, good for quick iteration.

A/B Mode

Click ⚡ A/B Mode in the header, then paste a modified DQ_SYSTEM into the Prompt B textarea. Every turn runs both prompts in parallel — results appear side by side. Column A is interactive; Column B is display-only for comparison.

Flagging questions

Click 🚩 Flag this question on any card. Choose a severity (🔴 Blocker, 🟡 Minor, 💡 Suggestion) and category before submitting. All flags in the session are exported with Copy flags for Slack.

Rule attribution

When a choice shows PERSONALIZATION or SOCIAL subtext, hover the ? icon to see which rule fired — memories exception, home profile exception, or project summary signal.

Export & Replay

⬇ Export session saves a JSON file with all questions, answers, raw JSON outputs, and flags. 📥 Load replay imports that file, fills in the scenario fields, and re-runs the stored answers through the current prompts — useful for regression testing after prompt edits.
